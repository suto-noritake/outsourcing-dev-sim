# Phase 1: 概念・数理モデルの設計

## 市場構造（v1）

1対1固定：委託元 A は1社のみ、受託会社 B も1社。両者が複数ラウンド `t = 1..T` にわたり
継続的に取引を繰り返す「反復ゲーム」としてモデル化する（市場競争・複数社対応は将来拡張）。

## 状態変数

- **A側**: 累計予算/資金余力 `Budget_A`、B への信頼度（評判）`R_t`、要求難易度 `D_t`
- **B側**: 保有AIクレジット `Funds_B_t`、選択する技術投資 `(m_t, n_t)`
  - `m_t`: 投入するモデル性能ティア（離散: Low / Mid / High / Frontier）
  - `n_t`: 投入エージェント数（整数）

## 直感的な2軸4象限フレームワーク（B社の状態を要約する軸）

詳細パラメータ（後述）はそのままでは直感的に語れないため、B社（受託会社）の状態を
**「技術優位度」×「資金体力」** という2つの合成指標に集約し、4象限で物語的に語れるようにする。
これは統計的な主成分ではなく、**結果を解釈・可視化するための"読み解きの軸"**として使う。

- **X軸: 技術優位度（Capability Margin）** = `Capability(m, n) − D_t`
  「今受けている案件の難易度に対して、技術力がどれだけ上回っている/下回っているか」
  → 低い（劣位）⇔ 高い（優位）
- **Y軸: 資金体力（Funding Runway）** = `Funds_B_t ÷ 平均バーンレート`
  「今のペースで資金を使い続けた場合、あと何ラウンド持ちこたえられるか」
  → 乏しい（枯渇寸前）⇔ 潤沢（余裕あり）

| | 資金体力：乏しい | 資金体力：潤沢 |
|---|---|---|
| **技術優位度：高い** | ② 宝の持ち腐れ／燃え尽き型<br>（技術はあるが運転資金が続かず倒産リスク大。ユーザー想定の「受託会社B」はここから出発しやすい） | ① 独走勝ち組型<br>（技術力・資金とも優位。案件エスカレーションを積極的に受け、市場を席巻） |
| **技術優位度：低い** | ④ 淘汰予備軍型<br>（技術も資金も苦しく、早期に市場退出しやすい） | ③ 物量型／時間稼ぎ型<br>（技術力不足でもリトライや低ティアモデル大量投入で当面は延命するが、失敗が続けば評判が悪化し③→④へ転落しやすい） |

- シミュレーション上では、各ラウンドでB社のこの2指標をプロットすると
  「①→②（技術投資しすぎて資金が枯渇していく）」「③→④（延命策が尽きて淘汰される）」
  といった**状態遷移の軌跡（フェーズポートレート）**として可視化できる
- 分析スクリプトの可視化に「技術優位度×資金体力の散布図・軌跡アニメーション」を必須の出力として含める
- 最終レポートでは、どの戦略（保守的/コスト最適/適応的）がどの象限に留まりやすいか、
  どの象限から抜け出せないか（トラップ）を主要な考察軸とする

## 技術力関数

```
Capability(m, n) = perf(m) * n^α        # α ∈ (0,1): エージェント数の収穫逓減（協調オーバーヘッド）
```
- `perf(m)` はティアごとの性能値（例: Low=1, Mid=2.5, High=4, Frontier=6）
- モデルティアが上がるほど**性能の伸び以上にクレジット単価が上がる**非線形コストを設定し、
  実際のLLM API料金体系の非対称性を反映する

## クレジット消費（実行コスト）

```
CreditCost(m, n, D) = k1 * cost_mult(m) * n * D * noise
```
- `cost_mult(m)`: ティアごとの単価倍率（Frontierほど急増）
- `noise`: 対数正規分布などの乱数（見積り誤差・手戻りの再現）
- 実行中に `Funds_B_t` が枯渇したら、その場で**倒産（シミュレーション終了）**

## 成功確率（技術力 vs 難易度）

```
P_success = sigmoid( β * (Capability(m, n) - D_t) )
```
- 技術力が難易度を上回るほど成功しやすいロジスティック関数
- `β` は「難易度と技術力の差」に対する成功確率の感度（急峻さ）を制御するパラメータ

## 所要時間

```
Time = time_const * D_t / Capability(m, n) * noise
```

## 検収・報酬・評判更新

- 成功時: B は報酬 `Payment_t`（= A が提示した予算）を得る。失敗時は
  部分報酬（設定可能パラメータ、既定0）のみ
- 評判は指数移動平均で更新: `R_t = λ * R_{t-1} + (1-λ) * success_t`
- **契約継続判定**: 連続失敗回数が閾値を超える、または `R_t` が下限を下回ると
  A が契約を打ち切り、シミュレーション終了

## A側の次ラウンド行動（発注方針の更新）

- 成功時: 難易度をエスカレーション `D_{t+1} = D_t * (1+γ)`（上限あり）、
  予算も難易度と評判に応じて増額 `Budget_{t+1} = c0 + c1 * D_{t+1} * f(R_t)`
- 失敗時: 難易度・予算を据え置き/減額

## B側の意思決定（戦略・スイープ対象）

`(m_t, n_t)` の選び方自体を**比較対象の戦略パラメータ**として複数用意し、
どの戦略が長期生存・利益最大化に有利かを検証する:

- **保守的戦略**: 予算内で成功確率を最大化する `(m,n)` を選ぶ（コスト度外視気味）
- **コスト最適戦略**: 必要最小限の投資に抑え、資金保全を優先する
- **適応戦略**: 過去の成功/失敗履歴に応じて投資レベルを調整する（学習的）

## 主要指標（メトリクス）

- 生存ラウンド数（倒産/契約打ち切りまでの期間）、最終利益・資金推移
- ラウンドごとの成功率、難易度到達点（どこまでエスカレーションできたか）
- `(m, n)` 選択と結果の相関、戦略間の生存率・利益率の比較

## 未確定パラメータ（実装時にsweep対象として明示）

`α, β, γ, λ, k1, cost_mult(·), perf(·), 部分報酬割合, 難易度初期値/分布, 初期資金`

これらは固定値で決め打ちせず、実験設計（`docs/experiment_design.md`）でレンジを定義してスイープする。

## 将来拡張（v1では対象外）

- 複数B社による入札競争（1対N, N対N）
- A側の複数案件同時発注、B側のリソース配分最適化
- 評判の外部公開（市場全体でのB社評判共有）
- 各社内の役割分業（企画/受託可否判断/設計/実装/QA）と、仕様の曖昧さ・難易度見積り誤差の
  情報非対称性モデル化（`docs/llm_experiments.md` のLLM実験結果を踏まえて、
  有望であれば抽象ABMにも因子として追加を検討）
