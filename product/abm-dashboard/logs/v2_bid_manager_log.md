# v2 受託可否判断ログ — Bid/Go-No-Go Manager

作成者: Bid/Go-No-Go Manager（私）
日時: 2026-08-19T19:11:13+09:00

概要:
クライアントの日本語フィードバックを受け、現行 v1（FastAPI + static/index.html）の実装を確認した上で、v2 で必須とすべき改善項目を優先順位付きで整理し、各受け入れ基準（Acceptance Criteria, AC）を具体的・検証可能に定義する。

前提確認（現状ソースに基づく事実）:
- static/index.html は UI 文言が英語主体で、ヘルプ説明がほぼ無く、パラメータ入力欄に説明がない（クライアント指摘の通り）。
- Chart.js による散布図/ヒストグラムは動作するが、canvas の CSS が流動的でウィンドウサイズで引き伸ばされ、図が歪む可能性がある（index.html の style に固定アスペクト比確保が無い）。
- サーバ起動は README に PowerShell 手順があるが、エンドユーザがダブルクリックで起動できる配慮は無い（現状はコマンドライン操作が必要）。

クライアント課題の技術的翻訳（優先度付け）:
1) 日本語化（必須/高）
 - 問題: 全て英語で、業務担当者が操作意図や結果意味を理解できない。
 - 要求: UI の全テキスト（見出し、ラベル、ボタン、凡例、ツールチップ、エラーメッセージ、README内のユーザー向け起動説明）を日本語化。

2) パラメータ説明の追加（必須/高）
 - 問題: 各種パラメータ名（alpha, beta, lam 等）に説明がない。
 - 要求: 全入力項目に日本語のインライン説明（ヘルプテキスト or tooltip）を追加。説明は業務的・平易な日本語で表現する（専門用語を避け、例と効果を短文で示す）。

3) 結果説明の追加（必須/高）
 - 問題: 出力が数値/英語ラベルだけで意味が分からない。
 - 要求: 集計数値（success_rate, bankruptcy_rate, mean_survival_rounds, mean_net_profit）と四象限ラベル（dominant_leader 等）に対し、日本語の短い「1行説明」および「行動示唆（1-2文）」を画面に併記する。

4) 1クリック/ダブルクリック起動（必須/中〜高）
 - 問題: ユーザがサーバ起動を面倒と感じている。
 - 要求: Windows 環境でダブルクリックですぐ起動してブラウザを開く手段を提供。候補:
   A) .bat ランチャー（推奨・短期対応）: product/abm-dashboard/launch_dashboard.bat を作成し、仮想環境の python 実行パスを使って uvicorn をバックグラウンドで起動（コンソールを最小化）し、既定のブラウザで http://127.0.0.1:8000 を開く。README に使い方を明記。
   B) PyInstaller で単一実行ファイル化（中長期）: 完全な .exe を生成して配布すればコマンド不要だが、CI でのビルド・テスト、ウィルススキャン等運用コストが増える。v2 の短期スコープでは A を推奨。
 - 制約: .bat はユーザ側の .venv のパスやポート競合に依存するため、README に既知の前提（.venv の位置・ポート解放の確認方法）を明記する。

5) 図の引き伸ばし／レイアウト改善（必須/高）
 - 問題: Chart.js の canvas が CSS により引き伸ばされ図が歪む。
 - 要求: Chart コンテナに CSS で比率（アスペクト比）を固定する、もしくは Chart.js の maintainAspectRatio:true を有効にしてレスポンシブかつ比率保持を保証する。さらに、モバイルとデスクトップのレイアウトを2通り用意し、ウィンドウ幅に応じた最大/最小幅・高さを設定する。

6) 表示文言のトーン（推奨/中）
 - 問題: 技術語が多く非専門家に刺さらない。
 - 要求: UI の全テキストを単に日本語化するだけでなく、ビジネストーン（非技術・意思決定者向け）の文言に書き換えることを強く推奨。例えば「success_rate」→「成功割合（契約継続の確率）」、ボタン「Run Simulation」→「シミュレーション実行」。
 - 備考: UI 文言の全面書き換えは UX と翻訳の観点からUXライターのレビュー推奨（別途作業）。

受け入れ基準（Acceptance Criteria: AC） — 検証可能なチェックリスト（番号付き）

必須（Must）

AC1 日本語フルローカライズ（表示文言）
 - AC1.1: UI 上の全てのラベル、見出し、ボタン、メニュー、凡例、グラフ軸ラベル、ポップアップ/アラート、エラーメッセージが日本語で表示されること。
 - AC1.2: README の "ユーザー向け起動手順" と "簡単な使い方" セクションが日本語で記載されていること。
 - 検証方法: ブラウザで UI を表示し、英語が一切残っていないことを目視・スクリーンショットで確認。

AC2 パラメータ説明（インラインヘルプ）
 - AC2.1: index.html の各入力フィールド（以下の全てを含む: alpha, beta, lam, k1, cost_curve_exponent, sigma_noise, gamma, partial_pay, r_min, max_consecutive_failures, difficulty_0, funds_0, difficulty_cap, budget_c0, budget_c1, max_rounds, strategy, n_trials, base_seed）に対して、日本語の短い説明（tooltip または helper text）を表示できること。
 - AC2.2: 各説明は必ず「業務向けの平易な日本語（1行〜2行）」で、以下の形式を満たすこと: パラメータ名（括弧）+ 要点 + 期待される効果の例。例: "alpha（影響減衰率）: エージェント数を増やす効果の逓減度合い。大きいほど人数を増やす効果が持続します。"
 - 検証方法: ホバーまたは情報アイコンをクリックして説明が表示されることを確認。サンプル表で全項目を網羅していることをチェックリストで確認。

AC3 結果説明（可視化と数値）
 - AC3.1: 集計指標（success_rate, bankruptcy_rate, mean_survival_rounds, mean_net_profit）それぞれに対して日本語の1行説明が表示されること（例: "成功割合: 試行ごとに契約を継続できた比率の平均。高いほど着実に契約を継続できる戦略です。"）。
 - AC3.2: 四象限ラベル（dominant_leader, cash_starved_specialist, deep_pockets_shallow_skills, exit_candidate）それぞれに日本語の短い意味説明と1行の「ビジネス上の示唆（例: 継続するか撤退を検討するか）」が表示されること。
 - AC3.3: 各 scatter の点にマウスオーバーしたときに日本語のツールチップでその試行の seed/strategy/最終値を表示すること。
 - 検証方法: UI 操作で説明文が確認できること。スクリーンショット保存。

AC4 ワンクリック（ダブルクリック）起動 — Windows ランチャー
 - AC4.1: product/abm-dashboard/launch_dashboard.bat をダブルクリックすると、ユーザの仮想環境（.venv）が既定位置にある場合に自動で uvicorn サーバが起動し、既定ブラウザでダッシュボード（http://127.0.0.1:8000/）が開くこと。
 - AC4.2: ランチャーはコンソールウィンドウを最小化/非表示で起動するオプションを備える（PowerShell の Start-Process -WindowStyle Hidden 等を用いる）。
 - AC4.3: 起動失敗時は日本語のエラーダイアログ（または console に日本語メッセージ）で、理由（ポート使用、.venv 未検出等）と対処法を示すこと。
 - AC4.4（情報）: README に .bat の利用方法と、.venv が標準と異なる場所にある場合の利用者向け手順を記載すること。
 - 検証方法: Windows 環境でダブルクリックしてブラウザが自動的に開き、UI が表示されること。

AC5 図の引き伸ばし防止（Chart レイアウト）
 - AC5.1: 散布図とヒストグラムがウィンドウサイズ変更時に縦横の比率が保たれること（歪まない）。具体的には Chart.js 設定で maintainAspectRatio=true を有効にし、CSS でチャートコンテナに max-width と max-height を設けること。
 - AC5.2: モバイル（幅<=480px）とデスクトップ（幅>=1024px）で表示が崩れないレスポンシブレイアウトを確認するためのチェックポイントを用意する（最低2種のスクリーンショットで確認）。
 - 検証方法: ブラウザでウィンドウ幅を変化させ、図が縦に引き伸ばされたり横に圧縮されないことを目視で確認。Chart.js の maintainAspectRatio をオフにしていた場合は fail とする。

必須ではないが強く推奨（Should）

AC6 UI 文言のビジネストーン全面書き換え（推奨）
 - AC6.1: UI文言を技術語中心から非技術的・業務決定者向けの日本語に書き換える提案を作成し、主要画面の文言案（50〜100語）を用意する。
 - AC6.2: UXライター（あるいは日本語ネイティブの事業担当）によるレビュー手順を定義する。
 - 検証方法: 文言案をレビュー担当が承認すること。

AC7 ドキュメントの平易化（任意）
 - AC7.1: README の "簡単な使い方" にスクリーンショットと日本語のステップバイステップ手順（3ステップ）を追加する。

優先度/Go-No-Go 判定（私の総合判断）

必須（今すぐ着手・リリース前に完了）
 - AC1 日本語化（フル）
 - AC2 パラメータ説明の追加
 - AC3 結果説明の追加
 - AC5 図の引き伸ばし修正
 - AC4 Windows ランチャー（.bat）を作成してユーザのダブルクリック運用をサポート（短期的実現性高）

推奨（次フェーズで実施可）
 - AC6 UI 文言のトーン全面見直し（UXライターと協働）
 - AC7 README の拡充（スクリーンショット等）

理由:
クライアントが指摘した "理解できない"/"起動が面倒"/"図が歪む" はユーザの体験を致命的に損ねるため、これらはリリース前に必須対応と判定する。一方、UIトーン全面改稿は効果が大きいがレビューと合意が必要なため短期集中で行うより次版での作業を推奨する。

 - AC3 結果説明: 0.5人日

 - AC4 .bat ランチャー作成とテスト: 0.25人日

実行上の注意・制約
 - .bat ランチャーは短期対応として有効だが、.venv の場所が環境依存な点を必ずユーザ向けに説明すること。組織で配布する場合は .bat の先頭で仮想環境検出ロジックを入れる（%~dp0 に基づく相対パス優先）。
 - PyInstaller による .exe 化は今後の検討項目。v2 スコープでは含めない。

## 次工程への申し送り（Architect 宛）

以下の Acceptance Criteria を満たす実装を設計してください（チェックリストとして利用可）。

1) UI 日本語化: static/index.html 内の全文言を日本語へ置換し、README のユーザ向け説明も日本語化すること。
2) 各入力フィールドに日本語のインラインヘルプ（tooltip/info アイコン）を実装する。パラメータ説明文は本ログの付録（下記）を参照して作成してください。
3) 集計値と四象限ラベルに日本語の短い説明と業務上の示唆（1行）を併記するUIを作ること。
4) Chart.js の設定で maintainAspectRatio=true を有効にし、チャートコンテナ CSS に max-width/max-height と最小値を設定してレイアウト崩れを防ぐこと。モバイルとデスクトップでの表示確認を含めること。
5) Windows 用 launcher: product/abm-dashboard/launch_dashboard.bat を作成し、ユーザがダブルクリックで起動→ブラウザ自動オープンできるようにすること。起動失敗時の簡易日本語エラー表示を用意すること。
6) 実装後は QA による回帰テスト（既存の test_api.py の全通、UI 日本語化の残存英語チェック、チャートのアスペクト比チェック）を必須とする。

-- 付録: 各パラメータの日本語説明（実装用直接テキスト案）
（各行: パラメータ名 — 日本語タイトル — 説明（1〜2行）例）

alpha — 影響減衰率 — エージェント数を増やす効果の逓減度合い。値が大きいほど、人数を増やしたときの効果が長く続きます。

beta — 競争強度 — 市場での競争圧力を表します。大きいほど競争が激しく、成功確率が下がります。

lam — 成功感度（λ） — 成功確率に影響する感度パラメータ。0〜1 の範囲で調整します。

k1 — 基礎能力係数 — 基本的な能力水準に影響する係数。値が大きいほど能力が増しやすいです。

cost_curve_exponent — コスト曲線指数 — コストがどの程度増加するかを決める指数。大きいほど追加費用が急増します。

sigma_noise — 変動ノイズ — 各ラウンドのランダム変動の強さ。値が大きいほど結果のばらつきが大きくなります。

gamma — 成長率係数 — 能力成長に関わる係数です。大きいほど能力が上がりやすくなります。

partial_pay — 部分支払い比率 — 収入が部分的に支払われる割合（0〜1）。

r_min — 最低報酬率 — 最低限期待される報酬の比率（0〜1）。

max_consecutive_failures — 連続失敗許容回数 — この回数を超えると終了扱いになります。

difficulty_0 — 初期難易度 — シミュレーション開始時の課題の難易度。

funds_0 — 初期資金 — エージェントの開始時点の資金。

difficulty_cap — 難易度上限 — 課題難易度が到達可能な最大値。

budget_c0 — 予算係数0 — コスト計算に使う定数（簡潔: 初期コストに関わる係数）。

budget_c1 — 予算係数1 — コスト計算に使う別の定数（増分コストに関わる係数）。

max_rounds — 1試行あたりの最大ラウンド数 — シミュレーションが長時間走らないための上限。

strategy — 戦略 — エージェントの行動方針を指定します。選択肢: conservative（保守的）, cost_optimal（コスト最適）, adaptive（適応型）。

n_trials — 試行回数 — Monte Carlo 試行の数（1〜500）。

base_seed — 乱数種の基点 — 再現性のための整数シード値。

四象限ラベルの日本語説明案:
- dominant_leader — 支配的リーダー: 能力・資金ともに高く、継続的に市場をリードできる候補。→ 示唆: 追加投資で拡大を検討。
- cash_starved_specialist — 資金枯渇型スペシャリスト: 能力は高いが資金不足で継続が難しい。→ 示唆: 資金支援で成長機会を狙うか撤退を検討。
- deep_pockets_shallow_skills — 資金潤沢・技能浅型: 資金はあるが能力が不足。→ 示唆: 教育投資や外部パートナーの活用を検討。
- exit_candidate — 撤退候補: 能力・資金ともに低く、早期撤退検討対象。→ 示唆: 早期撤退／事業売却を検討。

以上。私は今回のクライアント要望を "理解不能・起動工数・図の歪み" の3点に要約し、これらは v2 リリースまでに必ず修正すべきと判断する。実装の際は上記 AC を受け入れ基準として厳密に検証してください。
